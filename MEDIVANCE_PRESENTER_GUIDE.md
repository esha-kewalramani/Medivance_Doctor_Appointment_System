## SLIDE 13 — SYSTEM ARCHITECTURE
- **Category:** SYSTEM BLUEPRINT
- **Title:** System Architecture
- **Connected Architecture Flow:**
  - **Users**: Patient (Mobile/Desktop) | Doctor (Tablet) | Admin (Workstation)
  - ↓
  - **Frontend**: Next.js 14 | React 18 | TypeScript | Tailwind CSS 3
  - ↓
  - **Application Logic**: Role routing, queue auto-pilot, AURA AI keyword engine, simulated payment
  - ↓
  - **Two Supported Data Modes**:
    - **Demo Mode**: Browser LocalStorage, sample data, no backend required (100% offline uptime).
    - **Supabase Mode**: Supabase Auth, PostgreSQL DB, Row-Level Security, Edge Functions.
  - **Deployment**: Vercel Global Edge Network.

### 🎙️ Talking Points:
> *"To conclude, Slide 13 illustrates our complete system architecture:*
> - *At the top are our **Users**: Patients on phones, doctors on clinic screens, and administrators on workstations.*
> - *They connect through our **Frontend**: Powered by Next.js 14, React, and Tailwind CSS.*
> - *The **Application Logic** manages role routing, the 30-minute queue timer, and the AURA AI assistant.*
> - *At the data level, MEDIVANCE supports **Two Modes**:*
>   - ***Demo Mode**: Stores sample data in browser LocalStorage so the system can run 100% offline during presentations without internet.*
>   - ***Supabase Mode**: Connects to real Supabase PostgreSQL database and authentication when configured.*
> - *Finally, the platform is deployed globally on **Vercel**.*
>
> *MEDIVANCE transforms outpatient healthcare into a fast, smooth, and modern experience for everyone.*
